📋 Price Change Request · downstream impact preview
Custom object + LWC

A custom Price_Change_Request__c object orchestrates effective-dated tier changes with a downstream impact preview shown before publish — affected DRs, open quotes, EDI in flight, PUI accrual estimate, customer notifications. Approval Process routes by dollar threshold.

  • Price_Change_Request__c custom object with effective_date, direction (forward/retroactive), proposer/approver fields
  • Apex aggregator queries DRs, Quotes, Orders, Forecast Schedule Lines, and PUI buckets to compute impact
  • Lightning Web Component modal renders the impact preview before approval
  • Approval Process for sign-off routing (declarative)
  • Schedule-Triggered Flow fires the price-protection JE on effective date
  • Record-Triggered Flow notifies affected forecast lines

Anypoint Platform › Design Center › Forecast Demand Publish
🔌
Mule Application · forecast-demand-publish-flow
Publishes hand-typed monthly forecasts to ERP / MES at month-level granularity
🔌
MuleSoft Anypoint orchestrates the demand-publish integration. The DataWeave mapping below preserves the per-month qty + price + phase from Forecast_Schedule_Line__c through to your ERP / MES / demand-planning tool — month-level granularity is honored end-to-end so the forecast your sales rep typed is the forecast supply planning consumes.

Mule Flow XML
<flow name="forecast-demand-publish">
  <scheduler>
    <scheduling-strategy>
      <fixed-frequency frequency="86400000"/>
    </scheduling-strategy>
  </scheduler>

  <!-- Pull approved forecast lines from SF -->
  <salesforce:query
    config-ref="SF_Mfg_Cloud">
    <salesforce:salesforce-query>
      SELECT Id, Year_Month__c, Qty__c,
             Unit_Price__c, Phase__c,
             Forecast_Scenario__r.Confidence__c,
             Part__r.SKU__c
      FROM Forecast_Schedule_Line__c
      WHERE Status__c = 'Approved'
    </salesforce:salesforce-query>
  </salesforce:query>

  <ee:transform>
    <!-- DataWeave below -->
  </ee:transform>

  <http:request
    config-ref="ERP_Demand_API"
    method="POST"
    path="/demand/import"/>
</flow>

output application/json
// Preserve month-level granularity
// Do NOT smooth · do NOT average

{
  source: "salesforce-forecast",
  publishedAt: now(),
  lines: payload map ((line, i) -> {
    sku: line.Part__r.SKU__c,
    yearMonth: line.Year_Month__c,
    qty: line.Qty__c as Number,
    unitPrice: line.Unit_Price__c as Number,
    revenue: (line.Qty__c as Number)
            * (line.Unit_Price__c as Number),
    phase: line.Phase__c,
    confidence: (line.Forecast_Scenario__r
                .Confidence__c as Number) / 100,
    weightedRevenue: (line.Qty__c as Number)
                   * (line.Unit_Price__c as Number)
                   * ((line.Forecast_Scenario__r
                      .Confidence__c as Number) / 100),
    canonicalKey: line.Id
  })
}
Why custom?
This Mule flow queries the canonical Forecast_Schedule_Line__c records directly and ships (part, year_month, qty, unit_price, phase, confidence) tuples to the downstream planning system — preserving the per-month detail the sales rep typed without any averaging or smoothing in transit.
Components
  • Anypoint Designer flow with DataWeave 2.0 transformer
  • Canonical schema for SKU × Year-Month × Qty × Unit Price tuples
  • Direct connector to ERP / MES demand API
  • Anypoint Monitor for flow health, DLQ for retries
Operational
Anypoint Monitor for flow health · DLQ for failed deliveries · CloudHub 2.0 or Runtime Fabric for execution · standard MuleSoft operations practice with alerting and on-call playbook.
